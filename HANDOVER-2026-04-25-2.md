## Key Decisions Made

- **Aesthetic**: Started with full paper aesthetic (Caveat + Kalam fonts, warm cream background, sketchy borders). Rahul pushed back twice — first asked for more readable body fonts, then for clean Geist Sans + slate palette throughout, keeping the *layouts* from the paper aesthetic but the *typography/colors* from the existing app. Final: Geist Sans, white cards on slate-50 background, terracotta as a brand-accent-only.
- **Vocabulary**: The existing `programs` table = courses (e.g. "ELEM 101"). The wireframe's "programs" = tracks (Primary/Elementary/etc.). To avoid renaming, we introduced `program_tracks` as a new table for the track concept and kept `programs` as the course catalog. `course_programs` maps courses → tracks; `teacher_programs` (despite the name) maps trainees → tracks.
- **Admin pages use paper components too** (not separate styling).
- **Per-course stats (not aggregated)** for the teacher drilldown: when a teacher is in 5 courses, they get 5 stacked stat blocks rather than one merged set of numbers. Rahul picked this over the recommended aggregate option.
- **Per-course Roster tab is the primary path** for assigning teachers to courses; the bulk `/admin/assignments` matrix is kept but de-emphasised.
- **Test accounts**: Rahul's row is flagged `is_test_account=true` so his testing doesn't pollute cohort/dashboard stats.

## Important Context

- **Supabase project ref**: `cwsbievybrfglbvchrvp` (NOT the meetings app project). Use `mcp__supabase__*` tools or fall back to REST against `$NEXT_PUBLIC_SUPABASE_URL` with the service role key from `.env.local`. The MCP `execute_sql` tool was throwing transient `crypto is not defined` errors during this session — REST is the reliable fallback.
- **Migration vocabulary catch**: `teacher_programs.program_id` references `program_tracks(id)` (not `programs(id)`). This is intentional but counterintuitive given the column name.
- **Auth callback** hydrates `profiles.admin_scope_center_id` from `teacher_centers` and `profiles.admin_scope_track_ids` from `trainees.pre_assigned_admin_scope_track_ids` on first sign-in. Existing users who signed in before the migration won't have admin scope — they need to sign out and sign in again, OR an admin needs to set their scope manually via `/admin/users/[id]`.
- **`is_test_account` column** is on `trainees` (not `profiles`). Filters in `/api/admin/cohort`, `/api/admin/dashboard`, `/api/admin/voice-perf`, and `/api/manager` use a `.eq('is_test_account', false)` query with a graceful fallback that retries without the filter if the column is missing (in case an older DB is hit).
- **Breadcrumb bug landmine**: many pages had `← Dashboard` or `← Cohort` ad-hoc breadcrumbs. The redesign moved most of those to `<AdminSubNav>` tabs. If you re-edit one of these pages and the user reports a broken back-link, check that you removed the old breadcrumb when adding the sub-tab strip.
- **Voice attempts**: To test `/admin/voice/[responseId]`, a known good test response is `a4ec8840-deca-4395-993b-2b365a5a3465` (Mayuri Saxena, 4/5, has multiple attempts — shows the score-history line nicely). Mayuri isn't in HSR/Elementary scope, so she won't appear in the cohort heatmap; the link from cohort → drilldown only lights up once an HSR teacher has voice attempts on the ELEM courses.
- **Build**: every change in this session passed `npm run lint` and `npx next build`. If you hit a TS narrowing error in API routes (e.g. `'never[]'`), it's usually because of inline default object literals — type the variable explicitly first.
